#סיפור The Update That Locked Everyone Out | קשה
On a Thursday evening, a team of developers at a small company released a new version of their application. The new version had a better design for the login page, and all the tests on the computers of the developers passed. The oldest developer decided to deploy it at six in the evening, so that users would see the new design the next morning.

At seven, the first messages arrived. Users could not log in. They entered the correct password, and the application said that the password was wrong. In one hour, the company received more than 500 messages from angry users. Some users thought that their account was attacked by hackers and changed their passwords, which only made the problem more confusing.

The developers checked the code again. Everything looked correct. Then one developer, Noa, noticed a small detail. On their own computers, the developers used a test database. On the real servers, the application used another database with a different configuration. In the real configuration, the passwords were stored in a different format, and the new login code did not understand this format.

The team had two possible plans: to fix the code that night or to return to the old version. The fix could take many hours, and nobody could promise that it would work. So the team returned to the old version in 20 minutes, and users could log in again.

The next day, the team fixed the code, and this time they tested it in an environment that was identical to the real servers. They also made a new rule: no deployment after four in the afternoon, and no deployment on a Friday. "A test is only useful," Noa said, "if it tests the same thing that users will use."

#סיפור How Websites Should Store Your Password | קשה
When you create an account on a website, you choose a password. Many people think that the website stores this password in its database, the same way it stores your name. A good website does not do this. If it did, every hacker who stole the database would also have the password of every user.

Instead, a good website uses a special function. The function receives the password and creates a long string of letters and numbers. This string looks like letters with no meaning, and it has two important features. First, the same password always creates the same string. Second, it is almost not possible to go back from the string to the password. The website stores only the string.

When you log in, the website does not compare your password with a stored password. It runs the function on the password that you entered and compares the result with the stored string. If they are the same, you entered the correct password. In this way, the website can check your password without knowing it.

However, this method has a weak side. Many people use simple passwords, such as "123456" or "password". Hackers can run the function on a huge list of popular passwords and create a list of their strings. If a string from a stolen database is on the list, the hacker knows the password. To make this harder, good websites add a special value, different for each user, to each password before they run the function. Now two users with the same password have different strings, and the hacker's list is useless.

No method can protect a password that is too simple. But a website that stores passwords correctly turns a stolen database from a terrible problem into a much smaller one.

#סיפור The Chatbot That Invented a Book | קשה
A student, Lior, had to write a short article about the history of computers. She asked a popular chatbot for help. In a few seconds, the chatbot wrote a clear and confident paragraph. It even gave her the name of a book, its writer, and the year of the book as evidence. Lior was happy and added the book to her article.

Her teacher checked the article and could not find the book. It did not exist. The writer was a real person, but he never wrote such a book. Lior was confused. Why would a computer invent a book?

The answer is connected to the way these chatbots work. A chatbot uses a language model. During training, the model reads a huge amount of text from the internet and learns patterns: which words usually appear after which words. When you ask a question, the model does not search a database of facts. It creates an answer, word after word, that looks like the answers it saw during training. Usually, this pattern produces correct information. But when the model does not have enough information, it can still produce an answer that looks perfect and is completely false.

Developers are trying to reduce the problem. Some chatbots now search the internet and show links to the websites where they found the information, so users can check them. Others are trained to say "I do not know" when they are not sure. But no chatbot is perfect yet.

Lior learned an important lesson. A chatbot can be a useful tool for ideas and for the first version of a text. But every fact, and in particular every book or article that it gives as evidence, must be checked in a reliable place. A confident answer is not always a true one.

#סיפור Latency Is Not the Same as Bandwidth | קשה
Omer pays for a very fast internet connection, but when he plays online games, his game is often slow. His character moves a little after he presses a button, and he loses games because of it. He called his internet company and asked for even more bandwidth. The company was happy to sell it to him, but the problem did not go away.

The reason is that Omer confused two different things: bandwidth and latency. Bandwidth is the amount of data that can travel through a connection in one second. Latency is the time that one small packet of data needs to travel from your computer to the server and back. A good way to understand this is a road. Bandwidth is the number of lanes on the road. Latency is the distance to the city where you want to go. A road with ten lanes does not help if the city is very far.

For watching videos, bandwidth is important, because a video needs a lot of data. For online games, latency is more important. A game sends only small amounts of data, but it needs to send them very quickly. If the game server is in another country, every packet needs to travel a long way, and nobody can make that way shorter.

There are other causes too. A wireless connection usually has higher latency than a cable. Other devices on the same network can also slow down each packet.

In the end, Omer made two changes. He connected his computer to the router with a cable, and he chose a game server in a nearer country. His latency dropped from 120 to 30 milliseconds, and his game felt fast again. He did not need to pay for more bandwidth at all.

#סיפור The Bug That Appeared Only at Midnight | קשה
A company that sells train tickets online received a strange report. Every night, for about one hour after midnight, some users could not buy tickets. The website showed an error, and then, at about one in the morning, everything worked again. During the day, the developers could never see the bug.

At first, the team thought that the servers were too busy at night. But the monitor showed that traffic at midnight was very low. Then they thought that a backup process was slowing down the database. They moved the backup to another hour, but the bug appeared again the next night, at the same time.

Finally, a developer named Yoni decided to stay at work all night and watch the system. At midnight, he saw the error in the log: "Date is in the past." He looked at the code and found the cause. The servers of the company were in another country, where the time was one hour behind the country of most users. The code that checked the date of the ticket used the time of the server, but the users chose dates in their own local time. For one hour every night, it was the next day for the users, but still the day before on the server. When a user tried to buy a ticket for "today," the server thought that the date was tomorrow, or sometimes that it was in the past.

The fix was simple: the team decided to store every time in one standard time and to change it to the local time of the user only on the screen. The bug never appeared again.

Yoni later said that the hardest part was not the fix. It was to believe that a bug can depend on the clock.

#סיפור Phishing Emails Are Getting Better | קשה
For many years, it was easy to notice a phishing email. It usually had spelling mistakes, strange English, and a story that was hard to believe: a person from far away who wanted to send you money, or a prize that you never entered. Most users learned to delete such emails quickly.

Today, things are different. Criminals use artificial intelligence to write emails in perfect English. The emails look exactly like real messages from banks, delivery companies, or the IT department of your own company. Some criminals even study the person on social media before they write. An email to a programmer may talk about a real job of his team and use the name of a real worker in his team.

So how can a user protect his data? The answer is to stop looking only at the language and to start looking at the request. Almost every phishing email asks you to do something quickly: click a link, open an attachment, enter a password, or send money. When a message creates a feeling that you must act now and asks for one of these actions, you should stop.

There are also some technical checks. Look at the address of the sender, not only at the name. Move the mouse over a link, without clicking, and see the real address of the website. If the email says that it comes from your bank, do not use the link in the email. Open the website of the bank in a new window, or call the bank.

Finally, if you clicked by mistake, report it at once. Many users are embarrassed and say nothing. But the IT team can often stop an attack if it knows about it in the first minutes.

#סיפור Why the Phone Battery Is Empty Before Evening | קשה
Two years ago, Maya's phone could work for a whole day. Now the battery is almost empty at four in the afternoon. Maya thinks that her phone is simply old, and she wants to buy a new one. But before she spends a lot of money, it is worth understanding what uses the battery.

The first cause is the screen. A bright screen is one of the biggest users of power in a phone. Many people keep the brightness very high all day, even when they are inside a building.

The second cause is applications that work in the background. Some applications continue to run when you are not using them. They check your location, download content, or send data to their servers. Each one uses only a little power, but 20 such applications together use a lot.

The third cause is the signal. When the phone is in a place with a weak signal, such as a train or a room far inside a big building, it uses more power to stay connected to the network. A phone that searches for a signal all day can lose a large part of its battery.

Finally, the battery becomes weaker with time. Every time the battery goes from full to empty, it loses a little of its capacity. After two years, many batteries keep only about 80 percent of their original capacity.

Users received the old copy from the cache, and only after 12 hours did the cache read the new price from the database.

The developers cleared the cache, and everyone saw the new price. After that, they changed the system: when a price changes in the database, the page of that product is deleted from the cache automatically. A cache makes a website fast, but only if it knows when its data is no longer true.

#סיפור A Message About a Package | בינוני

#סיפור What Your Smartwatch Knows | בינוני
A smartwatch is a small computer on your hand. It knows how many steps you walk, checks your heart, follows your sleep and, in many models, knows your location all day. All this data goes to an application on your phone and usually to the servers of the company that made the watch.

This information can be very useful. It can show you that you sleep badly or that you do not move enough. Some watches even send an alert when they notice a dangerous problem with the heart.

But this data is also very personal. In one well-known story, an application for running showed a public map with the running routes of its users. The company did not think about the danger. But the map showed the routes of soldiers inside secret places of the army. Before you use a smartwatch, check which data it shares, who can see it, and if you can turn off the sharing of your location.

#סיפור The Printer That Opened a Door | בינוני
When a company thinks about security, it usually thinks about computers and phones. But today, many other devices are connected to the network: printers, cameras, smart speakers, even the coffee machine in the kitchen. Each of these devices is a small computer, and each one can have vulnerabilities.

In one company, hackers entered the network through a printer. The printer had an old version of its software, and nobody had updated it for five years, because nobody thought of a printer as a computer. Its password was still the standard password that came with the printer. From the printer, the hackers could see other devices on the same network and move to the servers of the company.

Security professionals recommend two simple steps. First, change the standard password of every device and update its software. Second, put such devices on a separate network, so that a weak printer cannot become a door to the important servers.

#סיפור Two Developers, One File | בינוני
Yael and Omer worked on the same application, and both of them changed the same file on the same day. Yael fixed a bug in a function at the start of the file. Omer changed the design of a button at the end of the file. When they tried to merge their work in the repository, the system merged the two changes automatically, because they were in different parts of the file.

The next week, things were different. Both of them changed the same line: Yael changed a value to 10, and Omer changed it to 20. This time, the system could not decide which change was correct. It stopped the merge and showed both versions, and a person had to choose.

Many new developers are afraid of this message. But it is not an error. It is the system saying: "I do not know what you want, so I will not choose alone." The solution is to talk: Yael and Omer discussed the two values for five minutes and chose the correct one together.
